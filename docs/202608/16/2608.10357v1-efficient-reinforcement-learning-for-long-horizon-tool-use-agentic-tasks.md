## 摘要
长时程工具使用智能体必须对用户目标、领域策略、工具调用、模拟器状态以及延迟的可验证奖励进行推理。强化学习（RL）天然适用于该场景，但多轮同策略（on-policy）推演会产生长上下文，而模型特定的注意力层可能需要自定义掩码和习得的 sink 归一化。我们提出了 SINKFLEX-RL，一个用于双控制工具使用环境中强化学习的模块化训练系统。该系统结合了 Gymnasium 兼容的环境封装器、VERL 风格的推演数据流、无需独立价值模型的组相对策略优化，以及一个 sink 感知的 FlexAttention 路径，旨在因果掩码和滑动窗口掩码下保持模型特定的 sink 缩放。在初步的 Tau2Bench 零售任务运行中，验证奖励（mean@1）从训练早期观察窗口中的 0.25 上升到后期的 0.44，同时训练得分和轨迹奖励代理指标也呈上升趋势。在固定配置的内存基准测试中，优化后的注意力路径在 4096 个 token 时将峰值 VRAM 从 28.06GB 降至 22.52GB，降低了 19.7%；在 8192 个 token 的配置下，测得使用 25.53GB，而 eager 基线则内存耗尽。这些结果展示了整合环境接口、强化学习数据流和注意力核设计对于内存可行的长时程智能体训练的价值。

## Abstract
Long-horizon tool-using agents must reason over user goals, domain policies, tool calls, simulator state, and delayed verifiable rewards. Reinforcement learning (RL) is a natural fit for this setting, but multi-turn on-policy rollouts create long contexts, while model-specific attention layers may require custom masks and learned sink normalization. We present SINKFLEX-RL, a modular training system for RL in dual-control tool-use environments. The system combines a Gymnasium-compatible environment wrapper, a VERL-style rollout dataflow, group-relative policy optimization without a separate value model, and a sink-aware FlexAttention path designed to preserve model-specific sink scaling under causal and sliding-window masks. In a preliminary Tau2Bench retail run, validation reward (mean@1) rises from 0.25 early in training to $0.44$ later in the observed training window, while training-score and trajectory-reward proxies also trend upward. In a fixed-configuration memory benchmark, the optimized attention path reduces peak VRAM from 28.06GB to 22.52GB at 4096 tokens, a $19.7\%$ reduction, and runs the measured 8192-token configuration using $25.53$~GB where the eager baseline runs out of memory. These results illustrate the value of integrating environment interfaces, RL dataflow, and attention-kernel design for memory-feasible long-horizon agent training.

## 1. 论文的核心问题与整体含义

- **研究背景**：长时程工具使用智能体（long-horizon tool-using agents）需要在多轮交互中理解用户目标、遵守领域策略、调用工具、跟踪模拟器状态，并依据延迟的、可验证的最终奖励进行学习。
- **核心矛盾**：强化学习（RL）适合此类顺序决策问题，但多轮在线策略推演会产生非常长的上下文；同时，模型特定的注意力层可能需要自定义掩码、习得的 sink 归一化，导致现有固定注意力内核难以直接适配训练。
- **系统瓶颈**：长序列下 eager attention 会带来注意力矩阵的二次方内存开销，导致高带宽显存不足；MoE 结构虽降低前馈成本，但不解决注意力瓶颈。
- **整体含义**：论文将智能体 RL 训练视为“系统集成问题”，目标是实现内存可行的长时程智能体训练，而非单纯提出新的 RL 算法或注意力理论。

## 2. 论文提出的方法论

- **系统名称**：SINKFLEX-RL，一个模块化训练系统，包含四个核心组件。
- **Gymnasium 兼容环境封装器**：
  - 将双控制工具使用环境（如 τ2-Bench）统一封装为 `reset/step` 接口。
  - 将模型输出路由到三类处理器：自然语言回复、工具调用、终止。
  - 隔离基准特定的用户模拟器、工具逻辑与奖励检查器，使环境可替换。
- **VERL 风格推演数据流**：
  - 推演 worker 负责采样多轮轨迹，将观测格式化为策略输入，解析动作并写入轨迹缓冲区。
  - 训练器只接收 token 级对数概率、动作掩码、轨迹奖励和元数据，不依赖具体工具实现。
- **无独立价值模型的 GRPO 更新**：
  - 对每个任务上下文 \(x\)，采样一组 \(G\) 条推演轨迹 \(y_1,\dots,y_G\)。
  - 使用组内归一化优势：
    \[
    \hat{A}_i = \frac{R_i - \mu(R_{1:G})}{\sigma(R_{1:G}) + \epsilon_A}
    \]
  - 对每个 token 使用重要性采样比 \(\rho_{i,t}\) 和裁剪比 \(\bar\rho_{i,t}\)，损失为：
    \[
    J_{i,t}(\theta) = \min(\rho_{i,t}\hat{A}_i,\ \bar\rho_{i,t}\hat{A}_i)
    \]
  - 总目标：
    \[
    L_{GRPO}(\theta)=-\frac{1}{\sum_i T_i}\sum_{i=1}^{G}\sum_{t=1}^{T_i} J_{i,t}(\theta)+\beta D_{KL}(\pi_\theta\|\pi_{ref})
    \]
  - 不训练单独的 critic 或 value network，以降低显存与计算开销。
- **Sink 感知 FlexAttention 路径**：
  - 利用零值 sink 的代数等价性：显式 sink token（sink logit \(s_\eta\)，value 为 0）可等价为对标准注意力输出进行缩放：
    \[
    \alpha_{sink} = \sigma(\ell - s_\eta),\quad O_{sink} = \alpha_{sink} O_{std}
    \]
    其中 \(\ell = \log\sum_i \exp(q\cdot k_i)\)。
  - 避免在 KV cache 中显式物化 sink token，减少内存占用。
  - 使用 PyTorch FlexAttention 组合因果掩码与滑动窗口掩码：
    \[
    M_{b,h,q,k} = \mathbf{1}[k\le q]\land \mathbf{1}[q-k\le w \lor k < p]
    \]
    其中 \(w\) 为局部窗口大小，\(p\) 为始终可见的前缀位置数。
  - 通过 `AOTAutograd` 和 `torch.compile` 融合 sink 缩放与注意力前向/反向路径，保留对 sink 参数 \(s_\eta\) 的梯度，而不物化 \(O(n^2)\) 的雅可比矩阵。
  - 优化点：使用编译与算子融合减少中间张量；mask 元数据跨 batch/head 广播，避免重复存储。

## 3. 实验设计

- **实验场景**：主要基于 τ2-Bench 的零售（retail）域，该环境具有双控制特性，即智能体和模拟用户都能影响世界状态。
- **实验 1：初步零售训练**
  - 目的：记录验证奖励及相关训练诊断在观察窗口内是否改善，而非隔离 GRPO 的因果效应。
  - 指标：
    - **Validation Reward (mean@1)**：每个任务采样一条验证轨迹，使用程序化验证的任务成功分数。
    - **Training Score Proxy**：训练过程中监控的仪表盘诊断指标；论文强调该标签历史上被称为“critic-style score”，但实际未训练 critic。
    - **Trajectory Reward Proxy**：原始 episode 奖励的滚动汇总。
  - 对比方式：仅对比同一训练运行的早期与后期数值，没有独立优化器基线。
- **实验 2：峰值显存缩放**
  - 对比对象：模型原生 eager attention 参考路径 vs. 优化后的 sink 感知 FlexAttention 路径。
  - 固定配置：相同模型、batch、训练配置。
  - 序列长度：1024、2048、4096、8192 tokens。
  - 指标：峰值高带宽显存占用（Peak VRAM in GB）。
  - 附加说明：实验未报告吞吐量、延迟或前向/反向数值等价性；结论仅限于观察到的峰值显存与执行可行性。

## 7. 优点

- **系统集成视角**：将环境、RL 数据流、注意力内核作为整体优化，解决实际训练瓶颈，而非孤立改进单一模块。
